# Лисквиз (Lisquiz) — Agent Operating System & Standards (ECC-Adapted)

Данный документ определяет стандарты разработки, архитектурные паттерны и протоколы качества для AI-агентов (Antigravity, Claude Code, Cursor, Copilot) при работе с кодовой базой «Лисквиз».
Базируется на принципах **ECC (Everything Claude Code / Agent Harness Optimization)** v2.2, адаптированных под стек проекта:
- **Backend**: Python 3.12, FastAPI, Pydantic v2, SQLite, Pytest/Unittest, GigaChat API
- **Frontend**: React 19, Vite, TypeScript, Framer Motion, Tailwind CSS / Tokens, Sferum MAX WebApp Bridge
- **ML & Gamification**: IRT 1PL Rasch, SymPy CAS, Knowledge DAG, Class Grove 2.0 (Liebig's Law)

---

## 1. Фундаментальные принципы (Core Principles)

1. **Plan Before Execute** — при реализации сложных фич, архитектурных изменений или рефакторинга сначала исследовать кодовую базу, сформулировать план и согласовать ключевые решения.
2. **Zero Silent Failures (Охотник за тихими ошибками)** — категорический запрет на скрытое подавление исключений (`except: pass`, пустые `.catch()`, неинформативные fallbacks). В режиме реального времени на уроке учитель и система должны мгновенно знать причину ошибки.
3. **Test-Driven & Verification** — ни одна критическая фича не считается завершенной без автоматизированных тестов. 100% прохождение тестовых наборов (`backend/venv/bin/python -m unittest`).
4. **Security & Anti-Leak First** — нулевая терпимость к утечкам секретов (GIGACHAT_CREDENTIALS, MAX_BOT_TOKEN). Все секреты строго в `.env` (в `.gitignore`).
5. **Mobile-First & Smooth Performance** — для клиентов Sferum/MAX на смартфонах школьников интерфейс должен выдавать 60 FPS без троттлинга процессора.

## 2. Backend & FastAPI Паттерны (fastapi-patterns)

### 2.1. Структура и разделение ответственности
- **Тонкие роутеры (`backend/app/api/`)**:
  - Роутер отвечает ТОЛЬКО за: определение HTTP-маршрута, валидацию Pydantic, извлечение зависимостей и вызов сервиса.
  - Никаких SQL-запросов, математических алгоритмов или бизнес-правил прямо в эндпоинтах.
- **Сервисный слой (`backend/app/services/`)**:
  - Вся бизнес-логика (расчет очков Либиха, начисление карточек гачи, шаги Rasch, поиск по учебникам) изолирована в сервисах.
- **Схемы Pydantic v2 (`Request` / `Response`)**:
  - Никогда не смешивать входящие и исходящие модели данных.
  - Использовать `model_dump()` вместо устаревшего `dict()`.
  - Никогда не возвращать секреты, токены или внутренние служебные поля в клиентских ответах.

### 2.2. Асинхронная гигиена
- Если эндпоинт объявлен как `async def`, он **не должен вызывать блокирующие синхронные функции** (тяжелые вычисления, блокирующий `requests`, синхронный sleep).
- Для внешних HTTP-запросов (GigaChat API) использовать строго асинхронный клиент `httpx.AsyncClient`.

## 3. Охотник за скрытыми ошибками (Silent Failure Hunter)

При написании или ревью любого кода проверять 5 уязвимых зон:

1. **Пустые блоки перехвата**:
   - ❌ `except Exception: return []`
   - ✅ Логировать `logger.warning("...", exc_info=True)` и возвращать контролируемый статус или ошибку.
2. **Опасные fallbacks**:
   - Fallback допустим только тогда, когда он явно предусмотрен спецификацией (например, переход на Mock-генератор при сбое сети) и сопровождается записью в лог.
3. **Потеря трассировки стека**:
   - Всегда пробрасывать контекст через `raise HTTPException(...) from err` или сохранять оригинальное исключение.
4. **Транзакционная целостность SQLite**:
   - Любые изменения нескольких таблиц (например, начисление очков + списание желудей + инвентарь) выполнять в единой транзакции `with conn:`.
5. **Обработка краевых случаев**:
   - Деление на 0 (например, точность ответов при 0 вопросах `correct / max(1, total)`).
   - Пустые списки учеников в лобби/сессии.

## 4. Frontend & Мобильная производительность (React / Sferum MAX)

1. **Аппаратные CSS-анимации**:
   - Для движения маскота, капель воды в Роще и всплывающих табличек использовать только `transform` (`translate3d`, `scale`) и `opacity`.
   - Не анимировать `top`, `left`, `width`, `height`, вызывающие принудительный пересчет макета (layout thrashing).
2. **Мемоизация списков и таймеров**:
   - В компонентах с частыми тиками (таймер вопроса `CountdownTimer`, лобби с подключением учеников `AvatarGrid`) использовать `React.memo`, `useCallback` и `useRef`, чтобы не перерисовывать всю страницу.
3. **Очистка ресурсов (Cleanup)**:
   - Всегда очищать таймеры (`clearInterval`), анимации (`cancelAnimationFrame`) и подписки WebSocket в return-функции `useEffect`.
4. **Тактильный отклик (MAX Haptics)**:
   - Использовать `hapticImpact('light' | 'medium')` при нажатии кнопок ответов и поливе Рощи для нативного ощущения в мобильном клиенте Сферума.
5. **Искоренение машинных шаблонов (Anti-AI-Slop Standard)**:
   - Полный запрет на клише нейросетей: фиолетовые линейные градиенты, гипертрофированное стекло (`backdrop-blur-md`), трекинговые заглавные метки (`tracking-widest uppercase text-xs`), разделение метаданных точками (`·`), принудительные стрелки `→` на кнопках, выделение отдельных слов в заголовках курсивом.
   - Опора на семантическую колористику OKLCH с единой цветовой температурой, структурированные границы (`border/60`), микросетки/SVG-текстуры вместо хаотичных теней `shadow-2xl`.
   - Швейцарская сетка / Bento-компоновка с высокой информационной плотностью; табличные цифры `tabular-nums` для всех очков, таймеров и счетчиков.
   - Безголовые примитивы доступности (Radix UI / React Aria) вместо самодельных `div`-модалок.

- [ ] **XSS защита**: имена учеников экранируются перед рендерингом на проекторе учителя.
- [ ] **Тесты**: запущен и успешно пройден тестовый набор:

