# 🧠 Архитектура и оптимизация ML-пайплайна генерации образовательных тестов «Лисквиз»

Исследование ML-контура для Всероссийского хакатона «Идея фикс» (Сферум, VK Образование, Минпросвещения РФ) в номинации «Продвинутая разработка» (Docker).

---

## 1. Сверхдешёвый гибридный пайплайн компьютерного зрения (Vision & OCR)

### Сравнительный анализ: VLM против Двухэтапного каскада

При оцифровке школьных материалов (типографские страницы учебников ФПУ, рукописные конспекты учащихся и записи мелом/маркером на классной доске) архитектурный выбор определяет экономику и скорость сервиса.

| Параметр сравнения | Подход А: Сквозные VLM (YandexGPT Vision, GigaChat Vision) | Подход Б: Двухэтапный каскад (Локальный OCR $\rightarrow$ Текст $\rightarrow$ Текстовая LLM) |
| :--- | :--- | :--- |
| **Стоимость за 1 фото** | 0,90 – 2,50 ₽ | **0,00 ₽ (локальный CPU OCR)** или **0,12 ₽ (Yandex Vision fallback)** + 0,05–0,08 ₽ (LLM) |
| **Сквозная задержка (Latency)** | 6,0 – 14,0 секунд | **2,0 – 3,5 секунды** (0,3 с OCR + 2,5 с LLM) |
| **Распознавание типографики** | Склонность к перефразированию | **Буквальная точность (WER < 2,0%)** |
| **Рукописный ввод и доска** | Высокий риск смысловых галлюцинаций | Высокая избирательность при гибридной маршрутизации |
| **Математический синтаксис** | Частое повреждение степеней и дробей | Высокая точность при трансляции в LaTeX |
| **Масштабируемость затрат** | Линейный рост затрат | **Стремление затрат к нулю** за счёт локального инференса |

### Оценка движков OCR для работы на CPU (без GPU)

* **RapidOCR (PP-OCRv4 в ONNX Runtime):** 180–320 мс на CPU, потребление RAM ~150 МБ, точность печатного текста CER < 1.2%. **Основной локальный выбор (0 ₽)**.
* **Yandex Vision OCR (`model: handwritten`):** 0,12 ₽ за страницу (в 10 раз дешевле YandexGPT Vision). Используется как прозрачный фолбэк, если средняя достоверность (confidence score) локального RapidOCR падает ниже 0.80.

## 2. Создание базы знаний школьной программы и оцифровка учебников

1. **Нормативная база:** Рубрикатор ФРП (edsoo.ru) + Кодификаторы КЭС ФИПИ. Канонический граф: Предмет $\rightarrow$ Класс $\rightarrow$ Раздел $\rightarrow$ Тема урока $\rightarrow$ КЭС.
2. **Парсинг учебников без LLM:** Использование `PyMuPDF4LLM` для структурированного Markdown со скоростью до 40 страниц в секунду.
3. **Векторная база:** **PostgreSQL 16 с расширением pgvector**. Исключает отдельный сервис Qdrant/Milvus, экономит до 2 ГБ RAM в Docker Compose.
4. **Эмбеддинги:** `intfloat/multilingual-e5-small` (384 измерения, 117M параметров, инференс на CPU ~15–20 мс, RAM ~450 МБ).

## 3. Архитектура «Нулевой стоимости» (Cache-First)

Пятиуровневый фильтр обработки запроса учителя:

| Уровень | Проверяемый сценарий | Механизм | Задержка | Стоимость |
| :--- | :--- | :--- | :--- | :--- |
| **L1: Exact Match** | Точный код темы ФРП | Хэш-поиск в PostgreSQL | 2–5 мс | **0,00 ₽** |
| **L2: Semantic Cache** | Неточная формулировка («дроби с разн знам») | Косинусный поиск pgvector ($\text{dist} \le 0.14$) | 15–35 мс | **0,00 ₽** |
| **L3: STEM Генератор** | Математика, физика, химия | Параметрический Python-шаблон (SymPy) | 3–8 мс | **0,00 ₽** |
| **L4: Банк вопросов** | История, общество, биология, литература | Выборка из офлайн-банка 10 000 тестов | 10–25 мс | **0,00 ₽** |
| **L5: LLM Fallback** | Редкие авторские темы | GigaChat Lite / DeepSeek V3 | 1,8–3,2 с | **0,078 ₽** |

### Параметрические генераторы математики (SymPy)
Для задач вида $a \cdot x + b = c$ скрипт на Python генерирует уникальные числа для каждого ученика, автоматически вычисляет верный корень и моделирует типичные детские ошибки для дистракторов (забыл сменить знак, умножил вместо деления). **Время: 0,3 мс, Стоимость: 0,00 ₽**.

## 4. Выбор оптимальной LLM

* **GigaChat Lite:** 0,065 ₽ за 1000 токенов (себестоимость викторины ~0,078 ₽, задержка ~2,5 с). Лучший выбор для работы внутри РФ.
* **Локальный Fine-Tuning SLM на GPU:** Отклонён. Аренда GPU стоит 5 000–11 000 ₽/мес, тогда как облачный API расходует бюджет по факту (Pay-as-you-go).

## 5. Защита от галлюцинаций и обработка формул в React

1. **Экранирование LaTeX в JSON:**
   Спецификация RFC 8259 требует удваивать обратный слэш в LaTeX командах при передаче через JSON: `\\frac{a}{b}`, `\\sqrt{x}`, `\\pm`.
2. **Отображение в React:**
   Использование легковесной библиотеки `react-katex` с перехватом ошибок:
   ```tsx
   import { InlineMath } from 'react-katex';
   // Рендеринг сегментов $formula$
   ```
3. **Символьная верификация математики:**
   Проверка формул на бэкенде через символьное ядро `sympy` перед отправкой ученикам.
