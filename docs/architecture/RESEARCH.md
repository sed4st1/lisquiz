# 🦊 Архитектурно-продуктовое исследование платформы интерактивных экспресс-викторин «Лисквиз»

Исследование подготовлено для Всероссийского хакатона «Идея фикс» (Сферум, VK Образование, Минпросвещения РФ) в номинации «Продвинутая разработка» (Docker).

---

## 1. Продуктовая механика и геймификация в экосистеме Сферум

### Киллер-фичи против существующих решений

Международные сервисы **Kahoot!** и **Quizizz** исторически ориентированы на открытый глобальный рынок, предполагая ручной ввод тестов педагогом либо поиск по неструктурированной пользовательской базе. Отечественный сервис **Wayground** решает задачу базового импортозамещения, но воспроизводит устаревшую изолированную механику тестирования без глубокой связки с инфраструктурой российских школ. 

Разрабатываемая платформа **«Лисквиз» (Lisquiz)** проектируется специально под контур экосистемы Сферум на платформе MAX и опирается на четыре ключевые функциональности, отсутствующие у конкурентов.

| Параметр сравнения | Kahoot! | Quizizz | Wayground | Лисквиз (Lisquiz) |
| :--- | :--- | :--- | :--- | :--- |
| **Связка с образовательными стандартами РФ** | Отсутствует | Отсутствует | Частичная (каталоги) | **Нативная генерация по рубрикатору ФРП и КЭС** |
| **Онбординг учащихся** | Ввод PIN на стороннем сайте | Ввод кода / Google SSO | Ввод кода / логин | **Бесшовный запуск в WebApp Сферум (0 кликов)** |
| **Отработка когнитивных дефицитов** | Платный режим Flashcards | Режим переигрывания | Статический просмотр ошибок | **Асинхронный микро-пуш через чат-бота (24–72 ч)** |
| **Модель вовлечения** | Жесткий индивидуальный рейтинг | Индивидуальный темп | Индивидуальный рейтинг | **Кооперативно-соревновательная «Роща класса»** |
| **Инфраструктурный контур** | Зарубежные облака (риск блокировок) | Зарубежные облака | Серверы РФ, браузер | **Интеграция с платформой MAX / Сферум, 152-ФЗ** |

#### Детализация ключевых преимуществ:
1. **Нативная генерация по рубрикатору Федеральных рабочих программ (ФРП РФ) и КЭС:** Преподавателю не требуется вручную составлять проверочные материалы. Модель ориентируется на таксономию Контролируемых элементов содержания (КЭС) Минпросвещения РФ. Учитель выбирает предмет, параллель и тему из официального классификатора, получая за 30 секунд сбалансированный пул заданий под конкретный урок.
2. **Бесшовный Zero-Friction Onboarding внутри платформы MAX/Сферум:** Отсутствуют внешние переходы, установка сторонних клиентов и ручная авторизация. Интеграция через MAX WebApp позволяет школьнику войти в игровую сессию кликом по интерактивному виджету в чате класса. Аутентификация осуществляется через криптографическую валидацию стартовых параметров платформы с сохранением анонимности персональных данных.
3. **Замкнутый цикл обучения (Closed-Loop Spaced Retrieval):** Платформа связывает фронтальный опрос на уроке с персональной микро-отработкой через сервисного чат-бота через 24 и 72 часа, трансформируя разовую викторину в непрерывный образовательный процесс.
4. **Кооперативно-соревновательная метафора «Роща класса»:** Традиционный индивидуальный лидерборд демотивирует отстающих учеников, провоцируя отказ от участия или слепое угадывание. Лисквиз внедряет параллельную командную механику: индивидуальные баллы конвертируются в общий пул энергии, который «выращивает» виртуальный лес класса под управлением маскота — лисёнка Спринта. Успех каждого школьника усиливает общую визуальную композицию, устраняя токсичную конкуренцию.

### Неинвазивный анти-чит и соревновательный баланс

В условиях хакатона и школьного контекста инвазивные методы прокторинга (захват видеокамеры, анализ фоновых процессов ОС) недопустимы с правовой и этической точек зрения. Защита академической честности обеспечивается анализом браузерных событий и математическим аппаратом скоринга.

#### 1. Клиентская валидация (Page Visibility API):
Сворачивание мини-приложения для поиска ответа в браузере или смежном чате детектируется системой. При первичном инциденте интерфейс выводит предупреждение от маскота (*«Спринт заметил, что ты отвлекся! Сосредоточься на вопросе»*). Повторный уход с экрана аннулирует скоростной бонус за текущий вопрос, сохраняя лишь базовую стоимость правильного ответа.

```typescript
export const registerAntiCheatWatchers = (onCheatAttempt: (reason: string) => void) => {
  let hiddenStartTime = 0;

  const handleVisibilityChange = () => {
    if (document.visibilityState === 'hidden') {
      hiddenStartTime = Date.now();
    } else if (document.visibilityState === 'visible') {
      const elapsed = Date.now() - hiddenStartTime;
      // Фиксация сворачивания WebApp или переключения вкладки
      if (elapsed > 1200) {
        onCheatAttempt('tab_switched');
      }
    }
  };

  const handleBlur = () => {
    onCheatAttempt('focus_lost');
  };

  document.addEventListener('visibilitychange', handleVisibilityChange);
  window.addEventListener('blur', handleBlur);

  return () => {
    document.removeEventListener('visibilitychange', handleVisibilityChange);
    window.removeEventListener('blur', handleBlur);
  };
};
```

#### 2. Параметрическая рандомизация задач:
Для естественно-научных дисциплин бэкенд получает от генератора шаблон задачи вида:
$$a \cdot x + b = c$$
где коэффициенты задаются диапазонами $[a \in (2..9), b \in (10..50)]$. Каждому подключенному сокету отправляется уникальный кортеж чисел при неизменной алгоритмической сути задачи, что нивелирует возможность списывания у соседа по парте.

#### 3. Двухфазная модель скоринга против спам-кликов:
$$S = \begin{cases} 0, & \text{если ответ неверен} \\ S_{base}, & \text{если } t < t_{read} \\ S_{base} + S_{speed} \cdot \left(1 - \frac{t - t_{read}}{T_{max} - t_{read}}\right)^\gamma, & \text{если } t_{read} \le t \le T_{max} \end{cases}$$

Когнитивный порог чтения $t_{read}$ вычисляется динамически исходя из объема текста вопроса (при средней скорости чтения школьника в 3 слова в секунду: $t_{read} = N_{words} \times 300\text{ мс}$). Нажатие варианта до истечения порога $t_{read}$ засчитывает правильный ответ, но полностью обнуляет скоростную надбавку $S_{speed}$. Коэффициент затухания $\gamma = 1.5$ сглаживает кривую начисления очков.

### Механика интервального повторения ошибок

Алгоритм отложенного повторения опирается на классическую модель удержания информации Германа Эббингауза:
$$R = e^{-\frac{t}{S}}$$
где $R$ — вероятность успешного воспроизведения материала, $t$ — время с момента проверки, $S$ — прочность следа памяти.

1. **Фиксация пробела (Урок, $t = 0$):** факт неверного ответа ученика на вопрос определенной микро-темы с фиксацией ошибочного дистрактора сохраняется в БД.
2. **Первая интервенция (Интервал 24 часа, $R \approx 0.4$–$0.5$):** Сервисный чат-бот платформы MAX инициирует push-уведомление с предложением помочь лисёнку Спринту разобрать сложную задачу. Ученику отправляются изоморфные задания (2 вопроса, 60–90 секунд).
3. **Вторая интервенция (Интервал 72 часа, $R \approx 0.6$):** Контрольный синтезирующий вопрос. В случае повторной ошибки показатель стабильности $S$ сбрасывается.
4. **Геймифицированное подкрепление:** Начисление валюты «Жёлуди знаний», открывающей кастомизацию маскота Спринта.

## 2. Модели ИИ и генерация викторин: SLM против Cloud LLM

### Вердикт по локальным SLM (1B–7B) на CPU:
Генерация проверочного теста из 5 заданий в строгом JSON требует порядка 700 токенов. Для **Qwen 2.5 7B Q4_K_M** на 4 vCPU время инференса составляет:
$$T = \frac{700\text{ токенов}}{4.5\text{ токенов/сек}} \approx 155\text{ секунд (более 2.5 минут)}$$
Это неприемлемо для экспресс-создания квиза (< 20 секунд). 

**Решение:**
- Основной контур: **Российские облачные API (YandexGPT 5.1 Pro / GigaChat API)** через паттерн «Стратегия».
- Резервный контур (fallback): компактная SLM (Qwen 2.5 3B в llama.cpp) на случай автономного контура.

## 3. Архитектура Real-Time подсистемы и стек

1. **Бэкенд:** FastAPI + WebSockets + Uvicorn.
2. **Хранилище сессий комнат:** In-memory `RoomStorageEngine` (dict + asyncio.Lock) с фасадом под Redis для масштабирования.
3. **База данных:** **PostgreSQL 16** (asyncpg + SQLAlchemy 2.0). Отказ от SQLite исключает блокировки базы при одновременной записи 40 ответов.
4. **Переподключение при разрыве связи:** Сессионный токен + снапшот `SYNC_STATE` (remaining_time_ms, has_answered, score).

## 5. Анимации маскота Спринта и Haptics

- **Формат анимаций:** **Rive (.riv)** — аппаратное ускорение на Canvas, вес рантайма < 140 КБ, файл анимации 15–30 КБ, стабильные 60 FPS в WebView.
- **Стейт-машина эмоций:**
  - `IDLE_OBSERVE` — нейтральное ожидание, шевеление ушками и хвостом.
  - `COUNTDOWN_DASH` — азартный бег с шарфом на последних 5 секундах.
  - `JOY_CELEBRATE` — прыжок с конфетти при правильном ответе.
  - `SUPER_STREAK` — золотое свечение шарфа при серии верных ответов.
  - `EMPATHY_REST` — поддерживающий жест при ошибке.
  - `GROVE_WATERING` — полив ростка в «Роще класса».
- **Haptic Feedback:** `HapticService` с вызовом `WebApp.HapticFeedback` и откатом на `navigator.vibrate`.

## 6. Безопасность и 152-ФЗ

- **Zero-PII:** Никаких ФИО, email или номеров телефонов.
- **Псевдонимизация:** $PID = \text{HMAC-SHA256}(user.id, \text{SECRET\_SALT})$.
- **Игровые никнеймы:** Сказочные псевдонимы или сокращенные имена.
- **Изоляция LLM:** Промпты содержат только тему и предмет.
